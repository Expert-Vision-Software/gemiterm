## Why

The gemiterm CLI has four interactive prompt sites that all hand-roll `node:readline` (`src/cli/utils/interactive-prompt.ts`, `src/cli/commands/{auth,delete,profile}-command.ts`). They work but they're limited: no arrow-key navigation, no per-prompt validation, no help text, no consistent theming, and no built-in handling for non-TTY callers. The `auth` profile menu in particular forces users to memorize five letter keys (`A`/`D`/`S`/`R`/`X`) when a single-select list would be more discoverable.

Separately, the `list` command is a pure non-interactive command. When a human runs `gemiterm list` (no flags) on a TTY, they get a flat 10-row text table dumped to stdout, with no way to navigate, change the sort, or filter interactively. For a user with hundreds of Gemini chats, this means dropping into a separate workflow (`--search`, `--sort`, `--limit`) for every question, or piping into `less`. The opportunity for a TUI-style browser is large and the implementation is bounded by `@inquirer/core`'s `createPrompt` + `usePagination` primitives.

`@inquirer/prompts` (modern Inquirer.js, the de-facto standard for Node CLI prompts) provides battle-tested replacements for every prompt we use, with built-in TTY detection, validation, theming, and graceful cancellation. `@inquirer/core` provides the lower-level `createPrompt` factory and `usePagination` hook for building custom TUIs like the chat-list browser. The library is the natural upgrade path; the only constraint is that the `debate-with-gemini` skill and the existing one-shot `gemiterm new "msg"` / `continue <id> "msg"` flows and the existing `gemiterm list --format json` output must keep their exact byte-for-byte stdout and exit behaviour.

## What Changes

- Add `@inquirer/prompts@^8.5.2` and `@inquirer/core@^11.2.1` as runtime dependencies in `package.json`. (Both are auto-installed when adding `@inquirer/prompts`; only the prompts package needs to be named explicitly.)
- Create a new facade module `src/cli/utils/prompts.ts` that wraps `@inquirer/prompts` with: a TTY gate, a shared theme, an `AbortController` for cancellation, and a typed error hierarchy (`NonInteractiveError`, `CancellationError`). The facade exposes `text`, `confirm`, `select`, and `browser` (the custom chat-list browser prompt). It is the only file in `src/` that imports from `@inquirer/prompts` or `@inquirer/core`.
- Migrate the chat REPL in `src/cli/utils/interactive-prompt.ts` to use `prompts.text({ message: "You" })` instead of `rl.question("You: ")`. Keep the `MessageHandler` / `runInteractiveLoop` / `InteractiveLoopOptions` public contract, the `/exit` and `/quit` slash commands, and the "Thinking… → Model:" output flow.
- Migrate the `auth` command's 5-letter profile menu to a `prompts.select` of named options. The private `promptInput` method on `AuthCommand` is preserved as a one-line shim that delegates to the facade, so `spyOn(command, "promptInput")` in `tests/cli/auth-command.test.ts` and `tests/integration/commands/auth.test.ts` keeps working.
- Migrate `delete-command.ts` and `profile-command.ts` the same way: `prompts.confirm` / `prompts.text` at the call sites, with `promptConfirmation` and `promptInput` reduced to facade-delegating shims.
- Add a new `--interactive/-i` opt-in flag to the `list` command. When the flag is set and `process.stdin.isTTY === true`, the command enters a TUI chat-list browser instead of dumping the text table. The browser supports paging (visible page with `↑`/`↓` navigation, `n`/`p` for next/prev page, `g`/`G` for top/bottom), interactive sorting (the `s` key opens a sort sub-menu with the same three modes as the non-interactive `--sort` flag: `recent`/`oldest`/`alpha`), and interactive filtering (the `/` key opens a search input that filters the list in real time using substring matching against `title`, mirroring the non-interactive `--search` flag). After picking a chat, the browser shows an action menu: view (invokes `fetch` against the picked id), export Markdown, export JSON, copy the conversation id, or back to list. The browser resolves on `q`, `esc`, or `--interactive` end-of-stream.
- The non-interactive forms of `gemiterm list` are **byte-equivalent** to the previous baseline. Concretely: `gemiterm list` (no flags) without `--interactive` still emits the same 4-column text table; `gemiterm list --format json` still emits the same `{ chats: ChatInfo[] }` JSON document; `gemiterm list --search "foo"` still forwards the search term to the mediator; `gemiterm list --all-profiles` still adds the `PROFILE` column; `gemiterm list --path out.txt` still writes to the file. The only way to enter the TUI is `gemiterm list -i` (or `--interactive`). If `gemiterm list -i` is invoked without a TTY, the facade's TTY gate throws `NonInteractiveError` with the message `gemiterm list -i requires a TTY; use --format json for machine-readable output`.
- The `gemiterm list -i --format json` and `gemiterm list -i --path …` combinations are errors: the TUI is its own output format and does not write to a file or stdout in JSON form. The error message is `Cannot use --interactive with --format or --path.` and the process exits with code 1.
- Add new unit tests for the facade (`tests/cli/utils/prompts.test.ts`), the chat REPL (`tests/cli/utils/interactive-prompt.test.ts`), and the chat-list browser (`tests/cli/utils/chat-list-browser.test.ts`).
- Add the `prompt-layer` spec capability under `openspec/specs/prompt-layer/spec.md` documenting the facade contract: TTY gate, prompt set, error mapping, theme choice, non-TTY error path.
- Add the `chat-list-browser` spec capability under `openspec/specs/chat-list-browser/spec.md` documenting the TUI: layout, keybindings, mode transitions, action menu, and the `--interactive` flag semantics.
- Extend the `interactive-prompt-loop` spec under `openspec/specs/interactive-prompt-loop/spec.md` with new scenarios: TTY-gate error, `ExitPromptError` → clean exit, validation failure, slash command contract.
- Extend the `commands` spec under `openspec/specs/commands/spec.md` with new requirements for `ListCommand` `--interactive` (the flag definition, the TTY requirement, the conflict with `--format` / `--path`, and the backward-compatibility contract that the non-interactive forms are byte-equivalent).

The `debate-with-gemini` skill and the non-interactive one-shot flows are unchanged. The REPL and the TUI are the only places Inquirer is invoked, and they are invoked only when `process.stdin.isTTY === true`. The one-shot `gemiterm new "msg"` path never calls a prompt and emits the existing `Conversation ID:` + `Model:` stdout byte-for-byte. The `gemiterm list --format json` path is untouched and emits the same `{ chats: ChatInfo[] }` JSON document.

## Capabilities

### New Capabilities

- `prompt-layer`: The TTY-gated facade over `@inquirer/prompts` that all interactive command sites consume. Defines the prompt set (text, confirm, select, browser), the cancellation contract, the non-TTY error path, the theme, and the error class hierarchy. This is the boundary that protects the rest of the CLI from Inquirer's TTY-only assumption.
- `chat-list-browser`: The interactive TUI for the `list` command. Defines the browser prompt's state machine (browse → search / sort / actions), the keybinding surface (`↑`/`↓`/`n`/`p`/`g`/`G`/`/`/`s`/`enter`/`q`/`esc`), the action menu after a chat is picked, the `--interactive` opt-in flag, the TTY requirement, and the conflict with `--format` / `--path`.

### Modified Capabilities

- `interactive-prompt-loop`: The chat REPL spec gains scenarios for: (a) the TTY-gate error when the REPL is invoked from a non-TTY context with no positional message and no `--prompt-file`, (b) `ExitPromptError` mapped to a clean exit with code 0 (preserves current behaviour), (c) `validationFailureMode` propagating validation errors back into the input loop without consuming the message, (d) the `/exit` and `/quit` slash commands remaining the only loop-terminating tokens. The `MessageHandler`, `runInteractiveLoop`, and `InteractiveLoopOptions` surface is unchanged.
- `commands`: The `ListCommand` requirement gains the `--interactive/-i` flag. The new requirements cover: the flag definition, the TTY requirement (`process.stdin.isTTY === true`), the conflict with `--format` / `--path`, and the backward-compatibility contract that the non-interactive forms of `gemiterm list` remain byte-equivalent to the previous baseline (no flag, `--format json`, `--search`, `--sort`, `--limit`, `--offset`, `--all`, `--all-profiles`, `--after`, `--before`, `--path`).

New specs: `openspec/specs/prompt-layer/spec.md`, `openspec/specs/chat-list-browser/spec.md`. New change artifacts: `openspec/changes/integrate-inquirer-prompts/{proposal,design,tasks}.md`.
- **Code modified:** `src/cli/utils/interactive-prompt.ts` (~40 lines, `rl.question` → `prompts.text`), `src/cli/commands/auth-command.ts` (~60 lines, letter-key menu → `prompts.select`, inline `promptInput` calls → `prompts.text`/`prompts.confirm`, `promptInput` method reduced to shim), `src/cli/commands/delete-command.ts` (~10 lines, `promptConfirmation` → `prompts.confirm`, method reduced to shim), `src/cli/commands/profile-command.ts` (~10 lines, same shape as auth), `src/cli/commands/list-command.ts` (~80 lines added: `--interactive` flag, the TUI branch, the conflict detection). Extended: `openspec/specs/interactive-prompt-loop/spec.md` (new scenarios), `openspec/specs/commands/spec.md` (new `ListCommand` requirements). `package.json` (1 new dep).
- **Dependencies added:** `@inquirer/prompts@^8.5.2` and `@inquirer/core@^11.2.1` (auto-installed transitively when adding `@inquirer/prompts`, but called out for clarity). Both ESM-only, Node `>=20.17.0`, Bun-compatible per the package README. No new transitive deps the gemiterm project must mediate; the rest of the chain (`@inquirer/ansi`, `@inquirer/figures`, `cli-width`, `signal-exit`, `mute-stream`, `fast-wrap-ansi`) is pure-runtime.
- **Tests:** Existing 623-test / 1241-`expect()`-call baseline (verified via `bun test` 2026-06-12) must remain at 0 fail with **zero changes to existing test files**. New tests for the facade, the REPL, and the browser are net-additive. The `spyOn(command, "promptInput")` and `spyOn(command, "promptConfirmation")` patterns in `tests/cli/*.test.ts` and `tests/integration/commands/*.test.ts` continue to work because the method names on the command classes are preserved as shims. The existing `tests/integration/commands/list.test.ts` must continue to pass without modification, which proves the byte-equivalent non-interactive contract.
- **Cross-cutting:** The `src/cli/commands/profile-command.ts:170-178` `promptInput` helper is currently duplicated verbatim from `auth-command.ts:170-178`. After the migration both reduce to identical one-line shims; a follow-up cleanup can hoist the shim to a shared base class, but that is out of scope for this change.
- **Mediation:** No new path/IO exemptions are needed. Inquirer reads from `process.stdin` and writes to `process.stdout` directly; the facade surfaces its own prompt calls, but the `node:readline` import the facade needs is a runtime concern, not a path/IO concern, and lives inside a `cli/utils/` module that the lint script does not currently check. The three exempt files (`src/infrastructure/path-utils.ts`, `src/infrastructure/io.ts`, `src/services/install-browser-service.ts`) remain the only ones allowed to import from `node:fs` / `node:path` / `node:os`. `scripts/lint-path-mediation.sh` continues to pass.
- **Skill compatibility:** The `debate-with-gemini` skill (https://github.com/Expert-Vision-Software/opencode-gemiterm-skills) uses only the one-shot `gemiterm new "msg"`, `gemiterm continue <id> "msg"`, and `gemiterm list --format json` forms. The first two never invoke a prompt; the third emits the same `{ chats: ChatInfo[] }` JSON it always did. The skill sees no change. The `gemiterm` skill's recommendation that `gemiterm auth` and `gemiterm continue` are "not automation-friendly" remains accurate; the TUI is a strictly human-UX addition.
- **Performance:** The browser prompt renders up to `pageSize` items at a time (configurable; default 15). For 1000+ chats the per-keystroke cost is O(n) over the filtered set, dominated by the `usePagination` `renderItem` call. Empirically (per the Inquirer research) this is sub-ms on modern hardware. No pagination or virtualisation is needed for the v1 UX; a follow-up change can add `useMemo` to the pre-filter pipeline if real users with thousands of chats report lag.
