## 1. Implementation

- [x] 1.1 In `src/cli/utils/prompts.ts`, add `useState`, `useKeypress`, `useMemo`, `useEffect` to the existing `@inquirer/core` import — no new dependency. (Originally also added `usePagination`, but the final implementation replaces it with a custom top-aligned slice; see 1.11.)
- [x] 1.2 Extend `BrowserConfig` with an optional `pageSize?: number` field. Test override only; production leaves it `undefined` to use the terminal-height path.
- [x] 1.3 Inside `browserPrompt`, add a `useMemo` for `pageSize` keyed on `[config.pageSize]`. Default path: `process.stdout.rows ?? 24` minus 4, multiplied by 0.8 (the 20% reduction), floored at 5.
- [x] 1.4 (Superseded by 1.8 / 1.11.) Original `←` / `→` handlers used a simple `±pageSize` clamp; replaced with the snap-to-first-row formula in 1.8, then the top-aligned `windowStart` formula in 1.11.
- [x] 1.5 (Superseded by 1.11.) Original render block used `usePagination`; replaced with the top-aligned `windowStart` slice in 1.11.
- [x] 1.6 Update the hint line to `"↑↓ navigate · ← → page · s sort · p profile · f favorites · enter pick · q quit"`.
- [x] 1.7 Add the `Page: X/Y` indicator to the title bar when `totalPages > 1`. `totalPages = max(1, ceil(N / pageSize))`; `currentPage = min(totalPages, floor(active / pageSize) + 1)`. The indicator is placed immediately after the chat count and is omitted when the list fits on a single page.
- [x] 1.8 (First bug fix.) Replace the simple `±pageSize` clamp in the `←` / `→` handlers (1.4) with a snap-to-first-row-of-new-page formula. For `→`: `currentPage = floor(active / pageSize)`, `newPage = min(totalPages - 1, currentPage + 1)`, `setActive(newPage * pageSize)` only when `newPage !== currentPage` (otherwise no-op, so `→` on the last page is a true no-op). For `←`: `currentPage = floor(active / pageSize)`, `newPage = max(0, currentPage - 1)`, `setActive(newPage * pageSize)` only when `newPage !== currentPage`.
- [x] 1.9 (First bug fix.) Pass `loop: false` to `usePagination` in the render block (1.5). The default `loop: true` caused the visible window to wrap around the ends of the list (e.g. a 20-item list at `pageSize: 5` with `active: 19` rendered `[c18, c19, c00, c01]`), which broke the cursor/page alignment. `loop: false` makes the fill stop at the list boundaries.
- [x] 1.10 (First bug fix.) Add `setActive(0)` to the `s` / `p` / `f` keypress handlers so the cursor is reset to the first row of the re-sorted / re-filtered list in the same re-render. Also add a `useEffect(() => setActive(0), [filteredSorted])` safety net to enforce the same reset for any future list-mutating path. The explicit-handler approach avoids a one-frame flicker that a `useEffect`-only approach would cause.
- [x] 1.11 (Second bug fix.) The user reported that even with `loop: false`, the cursor landed in the *middle* of the new page after `→` (e.g. `→` from page 1 to page 2 rendered `[c16, c15, c14, c13, c12]` with the cursor on `c14`). This was because `usePagination` centers the cursor on the visible window — the page indicator and the visible window disagreed, and each page had 2 items of overlap with the previous page. The fix is to **remove `usePagination` entirely** and replace it with a custom top-aligned render driven by a `useState<number>(windowStart)`:
  - `const [windowStart, setWindowStart] = useState<number>(0);` declared alongside `active`.
  - `←` / `→` handlers set both `setWindowStart(newPage * pageSize)` and `setActive(newPage * pageSize)`. The new page is a clean slice, cursor on the first row.
  - `↓` / `↑` handlers: cursor moves by 1 within the window; window scrolls by 1 when the cursor reaches the bottom (`↓`) or top (`↑`) edge. After the scroll, the cursor lands at the new edge of the scrolled window.
  - Render block: `filteredSorted.slice(windowStart, windowStart + pageSize)`, `renderRow` called only on visible items, cursor computed by reference (`item === filteredSorted[safeActive]`).
  - The `s` / `p` / `f` handlers and the `useEffect` for `[filteredSorted]` now reset both `setActive(0)` and `setWindowStart(0)`.
  - `@inquirer/core`'s `usePagination` is no longer imported.
